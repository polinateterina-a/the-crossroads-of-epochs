# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (MVP)

## 1. Цель

Разработать интерактивную веб-платформу «Перекрёсток эпох», которая позволяет пользователю совершить аудиовизуальное путешествие по дореволюционному Красноярску через сопоставление исторических и современных фотографий с одновременным прослушиванием реконструированных звуковых ландшафтов.

**Ключевые задачи ТЗ:**
- Реализовать веб-приложение с интерактивной картой, содержащей 4 локации пешеходного маршрута.
- Обеспечить возможность поиска экскурсии и переключения между режимами отображения (современный Красноярск — дореволюционный Красноярск).
- Создать для каждой локации карточку с двумя фотографиями («было/стало»), аудиоплеером и историческим описанием.
- Обеспечить удобство использования.

> **Форма поставки (MVP):**  
> Рабочий веб-сайт, развёрнутый на тестовом сервере, доступный через браузер без установки.

## 2. Описание информационной системы

Платформа «Перекрёсток эпох» — это веб-приложение с клиент-серверной архитектурой, состоящее из:

| Компонент | Описание |
|-----------|----------|
| **Фронтенд** | Веб-интерфейс на HTML/CSS/JS, отображающий карту, поиск, карточки локаций и аудиоплеер |
| **Бэкенд** | Сервер на Python/Flask, обрабатывающий API-запросы, работающий с базой данных и файловым хранилищем |
| **База данных** | SQLite, хранящая информацию о городах, экскурсиях, локациях |
| **Файловое хранилище** | Директория на сервере для хранения фотографий и аудиофайлов |

### Модули системы

| Модуль | Назначение |
|--------|------------|
| **Модуль карты** | Отображение интерактивной карты (OpenStreetMap) с метками локаций |
| **Модуль поиска** | Поиск экскурсий по названию и описанию |
| **Модуль экскурсии** | Отображение списка локаций, входящих в экскурсию |
| **Модуль карточки локации** | Отображение фото, слайдера «было/стало», аудиоплеера и текста |
| **Модуль переключения времени** | Переключение отображения карты между современным и дореволюционным состоянием |
| **Административный модуль** | Добавление и редактирование экскурсий и локаций (в MVP — через админ-панель) |

### Объекты системы

| Объект | Атрибуты |
|--------|----------|
| **Город** | id, название, описание |
| **Экскурсия** | id, название города, описание, список локаций |
| **Локация** | id, название, координаты (lat/lng), историческое фото, современное фото, аудиофайл, описание, год, теги |
| **Пользователь** | (в MVP не требуется регистрация, только сессия) |

## 3. Функциональные требования

### Модуль карты

| ID | Требование | Приоритет |
|----|------------|-----------|
| F1.1 | Приложение должно отображать интерактивную карту на базе OpenStreetMap | Must |
| F1.2 | Карта должна иметь возможность приближения/отдаления (зум) и перемещения (драг-н-дроп) | Must |
| F1.3 | На карте должны быть размещены маркеры всех локаций, входящих в экскурсию | Must |
| F1.4 | При клике на маркер должна открываться карточка с краткой информацией о локации | Must |
| F1.5 | Должна быть возможность переключения отображения карты между современным Красноярском и дореволюционным Красноярском (смена карт или наложение исторического слоя) | Must |

### Модуль поиска экскурсий

| ID | Требование | Приоритет |
|----|------------|-----------|
| F2.1 | На главной странице должно быть поле поиска | Must |
| F2.2 | Поиск по названию экскурсии, названиям локаций и тегам | Must |
| F2.3 | При выборе экскурсии из результатов поиска должен открываться её маршрут на карте | Must |
| F2.4 | Если экскурсия не найдена, должно отображаться сообщение «Ничего не найдено» | Must |

### Модуль экскурсии

| ID | Требование | Приоритет |
|----|------------|-----------|
| F3.1 | Экскурсия должна включать 4 локации, связанные пешеходным маршрутом | Must |
| F3.2 | Локации должны отображаться на карте в порядке маршрута | Must |
| F3.3 | Должна быть возможность переключаться между локациями (следующая/предыдущая) | Must |
| F3.4 | Должна отображаться общая информация об экскурсии (название, описание, протяжённость, время прохождения) | Should |

### Модуль карточки локации

| ID | Требование | Приоритет |
|----|------------|-----------|
| F4.1 | При клике на локацию должно открываться модальное окно с полной информацией о локации | Must |
| F4.2 | Модальное окно должно содержать слайдер «Было/Стало» для переключения между историческим и современным фото | Must |
| F4.3 | Модальное окно должно содержать аудиоплеер для воспроизведения звуковой реконструкции | Must |
| F4.4 | Модальное окно должно содержать историческое описание локации (200–300 слов) | Must |
| F4.5 | Модальное окно должно содержать год постройки/период и теги | Should |
| F4.6 | Модальное окно должно закрываться по кнопке «X» или клику вне окна | Must |

### Модуль аудиоплеера

| ID | Требование | Приоритет |
|----|------------|-----------|
| F5.1 | Аудиоплеер должен поддерживать воспроизведение и паузу | Must |
| F5.2 | Аудиоплеер должен отображать текущее время воспроизведения и общую длительность | Must |
| F5.3 | Должна быть возможность перемотки | Must |
| F5.4 | При закрытии модального окна воспроизведение аудио должно автоматически останавливаться | Must |
| F5.5 | Аудиофайлы должны быть в формате MP3 | Must |

### Административный модуль

| ID | Требование | Приоритет |
|----|------------|-----------|
| F6.1 | Администратор должен иметь доступ к админ-панели через пароль | Must |
| F6.2 | Администратор должен иметь возможность добавлять новые экскурсии | Must |
| F6.3 | Администратор должен иметь возможность добавлять новые локации в экскурсию | Must |
| F6.4 | Администратор должен иметь возможность редактировать существующие локации | Must |
| F6.5 | Для загрузки фото и аудио используется форма с указанием пути к файлам (в MVP — ручное размещение файлов на сервере) | Must |

### Приоритизация требований (MoSCoW)

| Категория | Описание |
|-----------|----------|
| **Must** (обязательно в MVP) | Вся функциональность с приоритетом Must из таблицы выше (карта, маркеры, поиск, карточка, аудиоплеер, админ-панель, 4 локации) |
| **Should** (очень желательно) | Отображение протяжённости и времени маршрута, теги, год постройки |
| **Could** (можно отложить) | Автоматическая загрузка файлов через форму (в MVP — ручное размещение на сервере) |
| **Will not** (в этом релизе) | Регистрация пользователей, сохранение прогресса, комментарии, оценки |

## 6. DEFINITION OF DONE

Задача считается **полностью завершённой**, если выполнены все пункты ниже:

### DoD для проекта в целом

1. Все функциональные требования (раздел 3) реализованы и работают
2. Все нефункциональные требования (раздел 4) выполнены
3. Все критерии приёмки (раздел 5) пройдены
4. Проведено тестирование на реальной фокус-группе (не менее 30 человек)
5. Получены положительные отзывы от не менее 70% тестировщиков
6. Код загружен в репозиторий GitHub с историей коммитов
7. Написана инструкция по развёртыванию и запуску
8. Проект развёрнут на тестовом сервере и доступен по ссылке
9. Отсутствуют критические баги, влияющие на работу пользователя
10. Проведена презентация проекта
